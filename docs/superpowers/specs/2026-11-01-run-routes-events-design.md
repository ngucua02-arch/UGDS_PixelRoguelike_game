# 单局路线与事件系统设计

日期：2026-11-01
状态：待玩家审阅
基线：`v0.1.0-vertical-slice`

## 目标

为每局增加三次路线决策和轻量战间事件，让相同的三场普通战斗与最终首领出现不同的风险、恢复和构筑取舍。所有路线都必须经过三场普通战斗，最终仍进入现有首领战。

## 已确认的产品规则

- 保留每局三场普通战斗和一场首领战。
- 每个战斗层开始前展示路线选择；路线可选稳妥路线或高压路线。
- 稳妥路线包含一段无战斗事件，然后进入该层标准编队。
- 高压路线跳过事件，进入该层更难的编队；击败后奖励卡从四件中选一件，而标准战斗仍从三件中选一件。
- 事件原型提供两个互斥选项：恢复 1 点生命，或从两件道具中选一件。道具补给替代本层战斗清场后的常规奖励；恢复选项保留常规战斗奖励。
- 生命已满时禁用恢复选项并明确说明原因；玩家仍可选择事件道具。
- 路线和事件只在本局有效，重开后回到新局初始状态。

## 玩家流程

1. 新局开始后打开路线图，当前层展示“稳妥路线”和“高压路线”；后续层及首领节点以未解锁状态显示。
2. 选择稳妥路线后进入事件面板。选择修复则恢复 1 点生命，再进入标准战斗；选择补给则从两件未拥有道具中选一件，再进入标准战斗，并标记该场战斗不再发放清场道具奖励。
3. 选择高压路线后直接进入该层挑战编队。挑战胜利后照常选择一件道具，但提供四个候选项。
4. 每场战斗后按现有流程结算奖励；若稳妥路线已在事件中选择道具，则跳过该场战斗后的普通奖励。第一、二场奖励处理完成后打开下一层路线图；第三场奖励或事件补给完成后进入现有首领战。
5. 胜负结算、重开、生命和已有构筑沿用当前规则。

## 路线内容

- 使用三层固定且经过策划的路线图，不加入程序化地图生成或路线存档。
- 每层的稳妥路线使用当前对应标准编队；高压路线使用同一层已有敌人类型的强化编队。首版不新增敌人原型。
- 三层路线节点具有固定、清楚的标签和收益说明。随机性继续来自现有道具候选池；路线结构本身先不随机，便于比较路线平衡。
- 最终首领节点始终位于三层路线之后，不受路线选择影响。

## 界面与交互

- 新增路线图面板，显示三层进度、两条当前可选路线及最终首领节点；路线按钮显示战斗难度、是否有事件和奖励候选数量。
- 新增事件面板，显示事件说明、恢复 / 道具补给选项，以及道具补给会替代本层战斗奖励的提示。
- 道具选择面板支持三或四个候选按钮，沿用当前道具名称、路线、效果和适配说明。
- 面板使用现有霓虹边框、深色底板与像素字体风格；首版不依赖新生成美术。

## 架构与数据流

- `Main.gd` 继续拥有单局状态、玩家、当前战斗、道具和首领；状态流新增 `route_select` 与 `event_choice`，并用当前层索引和奖励抑制标记控制转移。
- 新增路线数据资源，记录每层的标准编队、高压编队、事件标识和挑战奖励候选数。关卡内容与流程代码分离。
- 新增路线图与事件面板场景。面板通过信号回传路线 ID 或事件选项，不直接改写玩家、房间或单局状态。
- 普通房胜利后仍由 `Main.gd` 打开奖励流程；路线选择决定候选数与是否抑制该层奖励，避免创建第二套道具应用路径。
- 所有路线选择、事件效果与奖励发放都由 `run_state` 校验；胜负、重复点击及重开不得重复结算。

## 边界情况

- 事件提供的道具从未拥有的道具中抽取；若可用道具不足两件，显示实际可用数量；没有可用道具时禁用补给并保留恢复选项。
- 恢复不会超过玩家最大生命。生命满格时明确禁用，不扣除、不跳过其他状态。
- 若玩家在事件后战斗中失败，不发放该战斗的清场奖励；已领取的事件效果仅在本局结算前有效。
- 重开时清空路线层数、事件选择、奖励抑制标记、挑战状态和已选道具。
- 每次路线和事件按钮回调均检查当前状态和索引，防止重复输入触发重复房间或奖励。

## 非目标

- 永久成长、货币、商店、解锁、存档与元进度。
- 无限制程序化路线、地图编辑器、路线分支回溯。
- 新敌人类型、新首领、额外普通战斗层或改变首领规则。
- 新的美术生成流程、音频系统、网络或多人功能。

## 验收标准

- 每局无论路线组合如何都恰好有三场普通战斗，之后进入原首领战。
- 开始新局和前两场战斗奖励后能到达正确的路线选择；第三场之后能正确进入首领战。
- 稳妥路线事件可正确恢复生命，或发放一件未拥有道具并抑制对应战斗的普通奖励。
- 高压路线确实使用该层挑战编队，胜利时显示四个道具候选并只允许选一件。
- 满生命、道具池不足、快速重复点击、战斗失败和重新开始都不会造成重复奖励、软锁或状态残留。
- UI 清楚展示路线风险、事件收益与奖励替代规则，且不遮挡战斗画面。
- Godot 场景导入与 Windows 导出成功；玩家收到可试玩入口后进行实际操作验收。

## 实施拆分建议

1. 先建立路线状态与数据资源，接入三层固定路线和路线图面板；两条路线暂时都进入标准战斗，确认层数与首领衔接。
2. 加入稳妥路线事件、恢复与替代道具奖励规则。
3. 加入各层高压编队及四选一道具候选，并完善奖励面板布局。
4. 做一次完整流程试玩交付；按玩家反馈调整难度、收益和信息可读性。
