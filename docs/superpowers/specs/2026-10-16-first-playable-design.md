# 首个可玩原型设计

## 状态

- 项目：霓虹 Roguelike 原型（暂定名）
- UGDS：v1.0
- 开发模式：原型
- 里程碑：首个可玩核心循环
- 任务级别：Level 0 — 设计 / 规划
- 日期：2026-10-16
- 审批状态：等待用户审阅

## 目标

验证一局短流程的俯视角房间战斗是否清晰、灵敏、可重复游玩，以及道具选择能否让每局战斗产生不同变化。本项目当前目标是可玩原型，不是内容完整的正式游戏。

## 玩家体验

玩家进入霓虹风格的战斗房间，使用 WASD 移动、鼠标瞄准射击、空格闪避。击败敌人后房间完成，玩家从随机道具奖励中选择一件，再带着当前构筑进入后续战斗。流程包含三间战斗房和一场 Boss 战。玩家胜利或失败后，本局结束并可快速重开。

建议的射击方式：按住鼠标左键持续射击。这是首版实现默认值，试玩后如手感不佳可以调整。

## 设计支柱

1. 在紧凑俯视角竞技场中提供清晰、灵敏的战斗体验。
2. 道具选择能明显改变战斗行为，而非只增加少量数值。
3. 一局流程短，有明确结局，且便于快速重开。
4. 使用像素风角色轮廓和适量霓虹强调色，同时保证战斗可读性。

## 开发范围

- 使用 Godot 4.x 开发 2D 游戏；具体编辑器版本待运行环境确认。
- 一名玩家角色，具备移动、鼠标瞄准、基础远程武器、生命值和闪避能力。
- 三间战斗房，包含简单的清房与切换流程。
- 两种攻击方式清晰、行为有区别的敌人。
- 一场 Boss 战，包含少量清晰可辨的攻击模式。
- 约 8 件仅在本局生效的道具；战斗后提供随机选择，其中至少 3 件会明显改变武器行为或形成有意义的战斗取舍。
- 提供显示生命值、房间进度和道具选择的基础 HUD。
- 提供胜利、失败状态和快速重开。
- 允许使用临时美术与音效；前期可用高对比度形状或占位精灵图，不要求最终品质素材。

## 暂不包含

- 永久成长、解锁树、商店、剧情战役、多人游戏、在线服务、大规模程序生成、本地化、最终品质美术音效和正式发布打包。
- 不复刻《霓虹深渊》的专有角色、美术、名称、关卡或其他鲜明内容；仅将其作为类型和体验参考。

## 建议阶段与验收标准

### 阶段一：基础战斗房间

玩家可以移动、瞄准、射击和闪避；能够攻击并击败一个敌人，也会受到伤害；失败后可以重开。射击与受伤反馈清楚可辨。验收时，项目须能在 Godot 中启动且没有解析或运行错误，并由开发者实际游玩验证循环。

### 阶段二：房间推进与奖励选择

清空房间后开放前进流程。加入少量道具和随机选择奖励，让所选道具改变本局战斗。验收时，玩家须能连续完成多间房，并在战斗中观察到所选道具的效果。

### 阶段三：完整短流程

加入第二种敌人，完成三间战斗房和一场 Boss 战，提供清晰区分的胜利、失败状态和重开功能。验收时，玩家须能从开局完整游玩到本局结局。

### 阶段四：游玩验证与调整

反复游玩，记录操作阻力、平衡和可读性问题；只根据实际证据调整，然后评估 UGDS Gameplay Gate。根据真实游玩证据决定继续推进（GO）、迭代（ITERATE）、转向（PIVOT）或终止（KILL）。

## 最小可玩目标

先完成一间战斗房：玩家操作正常，有一个敌人、清晰的伤害反馈、清房状态和一个能改变战斗的道具选择；随后可进入第二次短遭遇，最终胜利或失败，并能重开。该阶段使用占位美术即可。

## 设计与运行约束

- 场景和资源结构保持简单、易理解：主流程场景、可复用的玩家与敌人场景、房间内容、奖励界面和少量道具数据。确有需要前不建立通用框架。
- 由一个明确的节点持有本局状态（生命值、已选道具、当前房间和结局）；房间清空、玩家死亡等状态通过直接信号通知。
- 只在有帮助时测试重要且确定的行为；自动化检查不能证明战斗是否有趣。
- Gameplay Gate 必须通过实际反复游玩完成，并记录构建版本、游玩环境、观察结果、优点、问题、限制和 GO / ITERATE / PIVOT / KILL 决策。

## 主要风险与待确认事项

- Godot 的具体版本和可执行文件位置尚未确认；本机 Godot 编辑器文档缓存指向 4.7 文档，但 PATH 中未找到命令行程序。
- 闪避时长、冷却、武器射速、伤害、房间时长和道具平衡应通过游玩调整，目前不预设最终数值。
- 弹幕和粒子过多、霓虹对比不当可能遮挡威胁；优先保证角色与危险提示清楚。
- 目标单局时长和原型开发时间仍待确认。

## 成功所需证据

- 项目可以在已安装的 Godot 编辑器或运行环境中启动。
- 新玩家经过简短提示后，能够理解移动、瞄准射击、闪避和推进方式，无需额外口头讲解。
- 一局可以完整到达胜利或失败，并能重开。
- 反复游玩时，道具选择至少能造成一种明显的战斗变化。
- 根据实际游玩完成 Gameplay Gate；仅有自动化检查不算通过。

## 自查

- 范围限制在短流程原型，与已确认的三间战斗房、两种敌人、一场 Boss 战和约 8 件道具相符。
- 已明确允许使用占位素材，且不包含永久成长。
- 数值平衡留待试玩迭代。
- 原型目标没有与未来完整商业游戏混为一谈；平台为 PC，Godot 4.x 的具体版本仍待确认。
