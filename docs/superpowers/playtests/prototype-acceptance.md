# 当前原型验收单

## 当前阶段

**预制作 / 可玩原型验收。** 目标是判断现有战斗与构筑循环是否值得冻结为核心，再制定垂直切片范围。本阶段不新增玩法系统，也不扩充道具和敌人数量。

本次试玩版本就是当前 Godot 项目，通过项目根目录 `开始试玩.lnk` 或 `开始试玩.bat` 启动。Godot 版本为 4.7.2 stable。最近一次技术检查曾通过编辑器扫描和主场景短时启动；它们不代替本单的实际游玩结果。

## 一局试玩

请从新开局玩到胜利或失败。失败也算有效试玩，不必为了通过验收而刻意重开多次。

1. **开局与操作：**移动、瞄准、射击和空格闪避是否正常；角色、敌人和弹幕是否看得清？
2. **普通房与奖励：**三间房能否按顺序推进？奖励选择是否容易比较，选中的道具能否在后续战斗中感受到？
3. **首领战：**首领是否显示？两类攻击是否有可辨认的预警，并留有反应时间？
4. **结束与重开：**胜负是否进入结算？重开后房间、生命和道具是否回到新局状态？
5. **整体感受：**记录本局大约用时、最卡或最不清楚的一处，以及你最希望优先改的一项。

不用逐项打分，按这句格式回报就够：

> 结果：胜利 / 失败；用时：约 __ 分钟；最顺的一点：__；最影响体验的一点：__；重开：正常 / 异常。

## 通过标准

- 没有阻止继续游玩的流程错误；即使失败也能正常结算并重开。
- 移动射击、房间推进和奖励选择可以不靠额外说明完成。
- 首领出现且攻击提示可读；若该项仍有问题，记录具体攻击或画面场景。
- 至少能说出一件所选道具对战斗造成的可观察变化，或明确说明为什么感受不到。

满足上述条件后，原型验收为 **GO**，下一步先定义垂直切片的完成品质和范围。任一核心流程被阻断，或战斗 / 奖励体验仍无法判断，则为 **ITERATE**，只修复试玩记录中影响最大的一至三项，再复验。输掉一局本身不代表验收失败。
